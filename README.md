# DaynAC

**Нейросетевой античит для Minecraft PvP-серверов.** Детектирует сторонние помощники наведения (AimBot / KillAura) по поведенческим паттернам ударов — без спидхак-чеков, пакетных сниферов и прочей классики. Модель обучается на датасетах, которые вы собираете сами на своём сервере.

Целевой сценарий — **1.9+ no-cooldown PvP**, где легитимно высокий CPS не является признаком чита: разделение легит/чит строится не на скорости кликов, а на геометрии и тайминге прицеливания.

## Как это работает

```
удары игрока ──► SnapshotTracker ──► HitData (20 признаков на удар)
                        │
                        ▼
              FeatureExtractor: окно из 16 ударов
              16×20 + 7 агрегатов = 327 признаков
                        │
                        ▼
              NeuralNetwork (327 → 128 → 64 → 32 → 1)
              чистый Kotlin, без ML-библиотек
                        │
                        ▼
              вероятность чита (0..1) ──► реакция сервера
```

**Признаки на каждый удар:** угол прицеливания, дистанция, интервал между ударами и его вариация, энтропия поворотов (abs/signed, yaw/pitch), джиттер, скорость по XZ, плавность вращения, snap-фактор (резкое дожатие прицела), микрокорректировки, рывок (jerk), прямолинейность поворота.

**Агрегаты по окну:** средний угол, коэффициенты вариации, энтропия распределения углов, автокорреляции lag-1 (механическая предсказуемость тайминга и прицела), R² линейного тренда угла (монотонное «дожатие» прицела).

**Реакция по порогам вероятности** (настраиваются в `config.yml`):

| Диапазон | Действие |
|---|---|
| < flag (0.65) | полное доверие |
| ≥ flag (0.65) | оповещение админам в чат |
| ≥ reduce (0.70) | плавное снижение урона |
| ≥ cancel (0.90) | полная отмена урона |
| ≥ punish (0.95) — мгновенный скор **и** среднее | кик / бан (настраивается) |

Защита от ложных срабатываний: множитель урона считается по **предыдущим** предсказаниям (первый удар всегда полный), автонаказание требует одновременного превышения порога и мгновенным скором, и средним по последним 10 ударам. Inference выполняется асинхронно — главный тик сервера не блокируется.

## Установка

### Требования

- Сервер **Paper 1.21.11** (или новнее той же мажорной версии)
- Java **21+**

### Установка готового jar

1. Скопируйте `DaynAC-<version>-all.jar` (артефакт shadowJar) в папку `plugins/` сервера.
2. Запустите сервер — плагин создаст `plugins/DaynAC/` с `config.yml`.
3. Настройте пороги под свой сервер (см. таблицу выше) и перезапустите.

Детекция **отключена, пока модель не обучена** — до сбора датасета и `/daynac train` плагин работает только как сборщик данных.

### Сборка из исходников

```bash
./gradlew build          # итоговый jar: build/libs/DaynAC-<version>-all.jar
```

Для локального тест-сервера прямо из проекта:

```bash
./gradlew runServer      # поднимет Paper 1.21.11 с плагином (2 ГБ RAM)
```

## Использование

Все команды требуют право `daynac.admin` (по умолчанию — op).

### Сбор датасета

1. Попросите доверенного игрока (или подключите второй аккаунт) поучаствовать в PvP-дуэли.
2. Включите запись:

   ```
   /daynac record <ник> legit    # игрок играет честно
   /daynac record <ник> cheat    # игрок играет с читом
   /daynac record <ник> off      # завершить запись
   ```

3. Вектор признаков записывается каждые 16 ударов (непересекающиеся окна) в `plugins/DaynAC/legit_vectors.csv` и `cheat_vectors.csv`. Игрок в режиме записи не проверяется детекцией — иммунитет на время сбора.

Для качественной модели нужны **оба класса** и желательно сопоставимое количество примеров каждого (сотни векторов на класс). Разнообразие ситуаций (дистанции, движение, разные жертвы) важнее количества.

### Обучение

```
/daynac train
```

- Разбивает датасет 80/20 (стратифицированно по классам), нормализует признаки по train-части.
- Обучает с early stopping по val loss и восстановлением лучших весов.
- Прогресс виден в реальном времени: живой прогресс-бар в action bar (игроку) и контрольные точки в чат каждые 10% эпох.
- По завершении: отчёт с train/val метриками и разрывом (переобучение), модель сохраняется в `model.dat`, детекция включается автоматически.

Результат обучения — вердикт о качестве датасета: большой разрыв train/val accuracy означает, что данных мало или они однообразны.

### Мониторинг

- `/daynac ver <ник>` — последний и средний скор игрока, количество ударов.
- `/daynac allinfo` — GUI (сундук 54 слота): все наблюдаемые игроки, скоры, вердикты, динамика последних ударов. ЛКМ по компасу — телепорт в режим наблюдателя.
- `/daynac info` — статистика датасета, состояние модели, текущие пороги.
- `/daynac debug` — вкл/выкл логгирование каждого удара в чат операторам.
- `/daynac reload` — перечитать `config.yml` (пороги применяются после перезапуска).

### Пример чат-оповещения

```
[DaynAC] Steve: необычный удар 0.871 > порога 0.65 — последние удары: 0.31 0.44 0.61 0.87 (средний: 0.54)
```

## Архитектура

```
src/main/kotlin/zov/grusha/daynAC/
├── DaynAC.kt              # точка входа: события, команды, запись датасета
├── tracking/
│   ├── CombatMath.kt      # геометрия: угол прицеливания, дистанция
│   ├── HitData.kt         # снимок признаков одного удара
│   ├── HitTracker.kt      # скользящее окно истории ударов
│   ├── PlayerSnapshot.kt  # дельты вращения/скорости за тик
│   └── SnapshotTracker.kt # тиковые снимки игроков, скользящие метрики
├── ml/
│   ├── FeatureExtractor.kt# окно ударов → вектор 327 признаков
│   ├── DatasetManager.kt  # CSV-датасеты легит/чит
│   └── NeuralNetwork.kt   # MLP + backprop, lock-free inference
├── detection/
│   └── DetectionEngine.kt # асинхронный inference, пороги, наказания
└── gui/
    └── AllInfoGUI.kt      # GUI наблюдения за игроками
```

Ключевые инженерные решения:

- **Нейросеть без зависимостей** — MLP 327→128→64→32→1 на чистом Kotlin (BCE + SGD + He-init + L2 + градиентный клиппинг). В проде не таскает PyTorch-рантайм и не требует Python.
- **Lock-free inference** — веса живут в immutable-снапшоте за `AtomicReference`: `predict()` не берёт локов, переобучение на живом сервере не блокирует детекцию ни на секунду.
- **Атомарная публикация модели** — `train`/`loadFrom` сериализованы мьютексом, файл модели пишется через tmp+rename: обрыв сервера не портит `model.dat`.
- **Защита от утечки данных** — непересекающиеся окна при записи датасета, стратифицированный split, нормализация только по train-части.
- **Никакой телеметрии** — всё локально: датасеты, модель, логи.

## Конфигурация

`plugins/DaynAC/config.yml`:

```yaml
hit-logging: false          # логгирование каждого удара

detection:
  flag-threshold: 0.65      # порог оповещения админам
  reduce-threshold: 0.70    # начало снижения урона
  cancel-threshold: 0.90    # полная отмена урона
  punish-threshold: 0.95    # автокик/бан (мгновенный скор И среднее)
  punish-enabled: true      # false = режим наблюдения (только оповещения)
  punish-action: kick       # none | kick | ban
  punish-reason: "KillAura (обнаружено нейросетью DaynAC)"
  max-recent-predictions: 10 # окно усреднения для урона и наказания
```

Порядок порогов валидируется при старте: `flag ≤ reduce < cancel ≤ punish`.
