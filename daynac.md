## 1. Что такое Daynac

**Daynac** — это антимошеннический плагин (anti-cheat) для серверов Minecraft (Paper API 1.21+), который использует **нейронную сеть** (машинное обучение) для обнаружения **KillAura** — читерских ассистентов наведения.

В отличие от классических античитов, которые используют жёсткие правила (например: «если угол наведения < 5°, значит читер»), Daynac **учится распознавать паттерны** на реальных данных. Он анализирует **комбинации** из десятков параметров движения и прицеливания, чтобы отличить человеческое поведение от машинного.

### Ключевые особенности:
- **Нейросеть на чистом Java** (без внешних ML-библиотек)
- **Асинхронная детекция** — inference выполняется в отдельных потоках, не нагружая основной тик сервера
- **158-мерный вектор признаков** для каждого анализа (8 ударов × 19 признаков + 6 агрегатов)
- **Градуированная система реагирования** — от предупреждения до бана
- **Сбор данных и обучение прямо на сервере** через команды

## 3. Жизненный цикл плагина

### Запуск (`onEnable` в `Daynac.java`):

1. **Загрузка конфигурации** — `saveDefaultConfig()` создаёт `config.yml` если его нет
2. **Загрузка модели** — пытается десериализовать `model.dat` из `plugins/daynac/`:
   - Если файл есть → загружает обученную нейросеть (`NeuralNetwork.loadFrom()`)
  - Если файла нет, он повреждён или размер входа не совпадает с текущим FeatureExtractor → создаёт новую нейросеть с 158 входами
3. **Инициализация компонентов** (строгий порядок):
   - `DatasetManager` — загружает CSV-файлы датасета
   - `PlayerTracker` — создаёт хранилища для снапшотов и ударов
   - `DetectionEngine` — создаёт пул из 2 потоков для inference
   - `CombatListener` — запускает тиковую задачу для записи снапшотов
   - `AllInfoGUI` — регистрирует обработчик кликов в инвентаре
4. **Проверка готовности модели** — если `model.dat` был загружен и датасет не пуст, модель помечается как «готова к детекции»
5. **Регистрация** слушателей событий и обработчика команды `/daynac`

### Выключение (`onDisable`):

1. **Сохранение модели** — сериализует нейросеть в `model.dat`
2. **Остановка пула inference** — `inferencePool.shutdownNow()`

## 4. Система трекинга: PlayerTracker и снапшоты

### PlayerSnapshot — снимок игрока

Каждый тик сервера (50 мс = 20 тиков/сек) для **каждого онлайн-игрока** записывается `PlayerSnapshot`:

| Поле | Тип | Описание |
|------|-----|----------|
| `timestamp` | `long` | Время записи (мс с эпохи Unix) |
| `yaw` | `float` | Горизонтальный угол поворота головы (°) |
| `pitch` | `float` | Вертикальный угол поворота головы (°) |
| `x`, `y`, `z` | `double` | Координаты игрока в мире |
| `velX`, `velY`, `velZ` | `double` | Вектор скорости |

### Хранение данных в PlayerTracker

PlayerTracker использует скользящие окна (LinkedList) на каждого игрока:

| Хранилище | Размер окна | Назначение |
|-----------|-------------|------------|
| `snapshots` | 40 тиков (2 сек) | История позиций и углов |
| `hitHistory` | 30 ударов | История всех записанных ударов |
| `yawDeltas` | 20 тиков | Приращения угла для расчёта джиттера |
| `pitchDeltas` | 20 тиков | Приращения питча для расчёта джиттера |
| `hitTimeDeltaHistory` | 10 ударов | Интервалы между ударами для CV |
| `previousAimAngle` | 1 значение | Предыдущий угол прицеливания для aimSnap |
| `lastHitTime` | 1 значение | Время последнего удара |

### Процесс записи снапшота (каждый тик):

```
[Каждый тик] → для каждого онлайн-игрока:
  1. Создать PlayerSnapshot(timestamp, yaw, pitch, x, y, z, velX, velY, velZ)
  2. Добавить в snapshots[player] (если > 40 → удалить старейший)
  3. Если есть предыдущий снапшот:
     - yawDelta = |текущий_yaw - предыдущий_yaw|  (с учётом перехода через 360°)
     - pitchDelta = |текущий_pitch - предыдущий_pitch|
     - Добавить в yawDeltas[player] и pitchDeltas[player]
```

### Процесс записи удара:

Когда игрок бьёт другого игрока:

```
1. Вычислить hitTimeDelta = текущее_время - время_последнего_удара
2. Сохранить hitTimeDelta в hitTimeDeltaHistory
3. Взять 3-4 последних снапшота (curr, prev, prevPrev, prevPrevPrev)
4. Вычислить aimAngle = угол между look_direction и direction_to_victim
5. Вычислить distance = расстояние до жертвы
6. Передать всё в FeatureExtractor.buildHitData() → получить HitData (19 признаков)
7. Добавить HitData в hitHistory[player]
```

## 5. Что такое HitData и из чего состоит каждый удар

`HitData` — это Java record с **19 числовыми полями**, описывающими один удар игрока по другому игроку. Каждое поле — это **признак** (feature), который так или иначе помогает отличить человека от чита.

### Все 19 признаков HitData:

#### Базовая ротация (4 признака):

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 0 | `yawDelta` | \|yaw_curr - yaw_prev\| | Насколько быстро игрок поворачивает голову горизонтально. Читы часто дают очень точные, постоянные повороты |
| 1 | `pitchDelta` | \|pitch_curr - pitch_prev\| | То же самое для вертикальной оси. У читеров часто нулевые или идеально постоянные изменения |
| 2 | `yawAccel` | \|yawDelta_i - yawDelta_{i-1}\| | Ускорение поворота. У человека оно хаотичное, у чита — плавное или нулевое |
| 3 | `pitchAccel` | \|pitchDelta_i - pitchDelta_{i-1}\| | Ускорение вертикальной ротации |

#### Качество прицеливания (2 признака):

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 4 | `aimAngle` | arccos(lookDir · toVictim) | Угол между направлением взгляда и направлением к жертве. У чита почти 0°, у человека колеблется |
| 5 | `distance` | ||eyeLocation - victimCenter|| | Расстояние до жертвы. Читы часто бьют с максимальной дистанции |

#### Тайминг (1 признак):

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 6 | `hitTimeDelta` | now - lastHitTime (мс) | Время между ударами. У читеров подозрительно стабильные интервалы (например, ровно 50 мс каждый раз) |

#### Джиттер (2 признака):

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 7 | `yawJitter` | stddev(yawDeltas за 20 тиков) | Разброс поворотов. У человека разброс большой и хаотичный, у чита — маленький или нулевой |
| 8 | `pitchJitter` | stddev(pitchDeltas за 20 тиков) | Разброс вертикальных движений |

#### Движение (1 признак):

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 9 | `speedXZ` | √(dx² + dz²) | Горизонтальная скорость. Некоторые читы бьют точно даже при высокой скорости движения |

#### Нейро-аура специфичные (9 признаков):

Эти признаки специально разработаны для обнаружения **«умных» аур** (neuro-aura), которые маскируются под человеческое поведение:

| # | Признак | Формула | Зачем нужен |
|---|---------|---------|-------------|
| 10 | `rotationSmoothness` | max(yawDelta) / avg(yawDelta) | Равномерность вращения. У человека max >> avg (есть резкие движения). У чита max ≈ avg (подозрительная равномерность) |
| 11 | `aimSnapFactor` | prevAimAngle / aimAngle | Фактор «щелчка» — как быстро прицел коррелировался к цели. Высокое значение = цель была далеко, а в следующий момент точно наведена = snap |
| 12 | `microAdjustCount` | count(yawDelta < 0.5° && > 0.001°) за 20 тиков | Количество микро-корректировок. Neuro-aura делает множество мелких подстроек, незаметных глазу |
| 13 | `straightLineRatio` | R² линейной регрессии yawDeltas | Линейность паттерна поворота. R² ≈ 1.0 = повороты идут по прямой линии (читерский паттерн). У человека R² → 0 |
| 14 | `headBodyAngleDiff` | \|yaw_головы - atan2(-dx, dz)\| | Разница между направлением взгляда и направлением движения тела. Читы часто смотрят на цель, двигаясь в совершенно другую сторону |
| 15 | `hitTimeCV` | stddev(hitTimes) / mean(hitTimes) | Коэффициент вариации интервалов ударов. Низкий CV = машинная стабильность. Высокий CV = человеческая вариативность |
| 16 | `yawEntropy` | -Σ(p·ln(p)) по 8 бинам | Энтропия Шеннона распределения горизонтальных поворотов. Низкая энтропия = повороты сконцентрированы в узком диапазоне (читерский паттерн) |
| 17 | `pitchEntropy` | -Σ(p·ln(p)) по 8 бинам | Энтропия вертикальных поворотов |
| 18 | `jerkValue` | \|accel_i - accel_{i-1}\| (усреднённо по yaw/pitch) | Анализ рывка ускорения мыши. В физическом смысле jerk — это скорость изменения ускорения (третья производная угла по времени). Snap-ауры дают всплески jerk, а слишком «идеально гладкие» траектории smooth-аур дают неестественно стабильный jerk |

В контексте античита jerk (рывок) для yaw/pitch — это третья производная угла по времени: сначала угол поворота, затем угловая скорость, затем угловое ускорение, и затем изменение углового ускорения.

### Как вычисляется каждый признак

Все вычисления происходят в `FeatureExtractor.buildHitData()`. Метод принимает:
- 3-4 последних снапшота (`prev`, `curr`, `prevPrev`, `prevPrevPrev`)
- `aimAngle` — рассчитанный в PlayerTracker через скалярное произведение
- `distance` — евклидово расстояние
- `hitTimeDelta` — разница во времени
- `recentYawDeltas` / `recentPitchDeltas` — последние 20 приращений углов
- `prevAimAngle` — угол прицеливания с предыдущего удара
- `recentHitTimes` — последние 10 интервалов для CV
- `moveDirYaw` — направление движения

## 6. Извлечение признаков: FeatureExtractor

### Как формируется вектор из 158 признаков

`FeatureExtractor.extract()` принимает список последних ударов (`List<HitData>`) и формирует **единый числовой вектор** размером 158:

```
Окно: 8 последних ударов
Признаков на удар: 19
Per-hit часть:  8 × 19 = 152 признака
Агрегаты:       6 признаков
Итого:          158 признаков
```

### Структура вектора (158 элементов):

```
[удар_1 × 19 признаков] [удар_2 × 19] ... [удар_8 × 19] [6 агрегатов]
 индекс 0-18             19-37              133-151        152-157
```

Если ударов меньше 8 — недостающие позиции заполняются нулями (zero-padding).

### 6 агрегатных признаков

Агрегатные признаки вычисляются **по всему окну** (всем 8 ударам) и дают общую картину:

| Индекс | Признак | Формула | Смысл |
|--------|---------|---------|-------|
| 152 | `avgAimAngle` | mean(aimAngle по окну) | Средний угол наведения. У читера ≈ 0°, у человека > 5° |
| 153 | `hitTimingAutocorr` | lag-1 автокорреляция hitTimeDelta | Насколько время между ударами повторяется. Высокая корреляция = машинная стабильность |
| 154 | `yawAutocorr` | lag-1 автокорреляция yawDelta | Насколько повороты повторяются из удара в удар |
| 155 | `CPS` | (hitCount-1) × 1000 / totalMs | Удары в секунду (Clicks Per Second). Очень высокий CPS → автокликер |
| 156 | `aimAngleVar` | variance(aimAngle по окну) | Дисперсия угла наведения. Низкая дисперсия = нечеловеческая стабильность |
| 157 | `yawStd` | stddev(yawDelta по окну) | Стандартное отклонение поворотов. У читера подозрительно маленькое |

### Автокорреляция (lag-1)

Автокорреляция измеряет, насколько значения последовательности **коррелируют сами с собой** со сдвигом в 1 позицию:

$$autocorr = \frac{\sum_{i=0}^{n-2}(x_i - \bar{x})(x_{i+1} - \bar{x})}{\sum_{i=0}^{n-1}(x_i - \bar{x})^2}$$

- **Высокая автокорреляция** (→ 1.0) = следующее значение предсказуемо из предыдущего (машинный паттерн)
- **Низкая автокорреляция** (→ 0) = значения случайные (человеческий паттерн)

## 7. Нейронная сеть: полное объяснение

### 7.1. Что такое нейросеть

Нейронная сеть (Neural Network) — это математическая функция, которая принимает на вход набор чисел (вектор признаков) и выдаёт число на выходе (вероятность). В нашем случае:

- **Вход**: 158 чисел, описывающих последние 8 ударов игрока
- **Выход**: одно число от 0.0 до 1.0 — вероятность того, что игрок использует KillAura

Сеть состоит из **слоёв нейронов**, соединённых **весовыми коэффициентами** (weights). Каждый нейрон:
1. Получает числа от нейронов предыдущего слоя
2. Умножает каждое число на свой вес
3. Складывает результаты, добавляет смещение (bias)
4. Пропускает сумму через **функцию активации**

### 7.2. Архитектура сети Daynac

```
Входной слой:  158 нейронов  (один на каждый признак)
         ↓
Скрытый слой 1: 128 нейронов  (ReLU)
         ↓
Скрытый слой 2: 64 нейрона   (ReLU)
         ↓
Скрытый слой 3: 32 нейрона   (ReLU)
         ↓
Выходной слой:  1 нейрон     (Sigmoid)
```

**Всего параметров (приблизительно):**
- Веса: 158×128 + 128×64 + 64×32 + 32×1 = 20 224 + 8 192 + 2 048 + 32 = **30 496 весов**
- Смещения: 128 + 64 + 32 + 1 = **225 bias**
- Итого: **~30 700 обучаемых параметров**

Плюс 158 значений `featureMean` и 158 значений `featureStd` для нормализации (вычисляются при обучении, не обучаются).

### 7.3. Активационные функции

#### ReLU (Rectified Linear Unit) — для скрытых слоёв

$$ReLU(x) = \max(0, x)$$

- Если `x > 0` → пропускает как есть
- Если `x ≤ 0` → возвращает 0

**Зачем**: Вносит **нелинейность** в сеть. Без активаций сеть, сколько бы слоёв ни имела, была бы эквивалентна одному линейному преобразованию. ReLU позволяет сети обучаться сложным нелинейным паттернам.

**Производная (для обратного распространения)**:
$$ReLU'(x) = \begin{cases} 1 & \text{если } x > 0 \\ 0 & \text{если } x \leq 0 \end{cases}$$

#### Sigmoid — для выходного слоя

$$\sigma(x) = \frac{1}{1 + e^{-x}}$$

- Преобразует любое число в диапазон (0, 1)
- Интерпретируется как **вероятность**

**Зачем**: Нам нужна вероятность от 0 до 1. Sigmoid идеально подходит для бинарной классификации (легит / читер).

**В коде**: Для предотвращения числового переполнения, значение `x` ограничивается диапазоном [-500, 500]:
```java
x = Math.max(-500, Math.min(500, x));
return 1.0 / (1.0 + Math.exp(-x));
```

### 7.4. Прямой проход (Forward Pass)

Это процесс **вычисления предсказания** по входному вектору. Шаги:

```
1. input[158]  →  нормализация Z-score  →  a₀[158]

2. Для каждого слоя l = 1, 2, 3, 4:
   Для каждого нейрона j в слое l:
     z_j = bias[l][j] + Σ(weights[l][j][k] * a_{l-1}[k])  для всех k
     
     Если это НЕ последний слой: a_j = ReLU(z_j)
     Если это последний слой:    a_j = Sigmoid(z_j)

3. Выход a₄[0] — это вероятность от 0 до 1
```

Конкретный путь данных:
```
raw_features[158]
     ↓ Z-score нормализация
normalized[158]
  ↓ 158×128 weights + 128 biases → ReLU
hidden1[128]
     ↓ 128×64 weights + 64 biases → ReLU
hidden2[64]
     ↓ 64×32 weights + 32 biases → ReLU
hidden3[32]
     ↓ 32×1 weights + 1 bias → Sigmoid
output[1] ∈ (0, 1)  ← вероятность KillAura
```

### 7.5. Функция потерь (Loss)

Используется **Binary Cross-Entropy (BCE)** — стандартная функция потерь для бинарной классификации:

$$L = -[y \cdot \ln(\hat{y} + \epsilon) + (1 - y) \cdot \ln(1 - \hat{y} + \epsilon)]$$

Где:
- $y$ — истинная метка (0.0 = легит, 1.0 = читер)
- $\hat{y}$ — предсказание сети (0..1)
- $\epsilon = 10^{-15}$ — малая константа для избежания $\ln(0)$

**Интуиция**:
- Если истинный ответ y=1 (читер), а сеть дала $\hat{y}$=0.01 → потеря **очень большая** (наказание за ошибку)
- Если истинный ответ y=1, а сеть дала $\hat{y}$=0.99 → потеря **почти нулевая** (правильный ответ)
- Функция «штрафует» сеть за уверенно неправильные ответы экспоненциально сильнее

### 7.6. Обратное распространение ошибки (Backpropagation)

Backpropagation — алгоритм вычисления **градиентов** (направления и величины коррекции) для каждого веса в сети.

#### Шаг 1: Вычислить дельту выходного слоя

Для BCE + Sigmoid, дельта выходного нейрона имеет элегантную форму:

$$\delta_{L} = \hat{y} - y$$

Это разница между предсказанием и правильным ответом. Оно же — градиент потерь по входу последнего нейрона.

#### Шаг 2: Распространить дельты назад

Для каждого скрытого слоя (от предпоследнего к первому):

$$\delta_l[j] = \left(\sum_{n} weights[l+1][n][j] \cdot \delta_{l+1}[n]\right) \cdot ReLU'(a_l[j])$$

Здесь:
- Сумма идёт по всем нейронам следующего слоя
- $ReLU'$ = 0 если нейрон был «выключен» (≤ 0), иначе 1
- Дельта **ограничивается** (clipping) в диапазоне [-5.0, +5.0]

#### Шаг 3: Обновить веса

Для каждого веса и bias в сети (см. раздел SGD ниже).

### 7.7. Обновление весов (SGD)

Используется **Stochastic Gradient Descent** (Стохастический градиентный спуск):

$$w_{new} = w_{old} - \eta \cdot grad$$
$$b_{new} = b_{old} - \eta \cdot \delta$$

Где:
- $\eta$ — **learning rate** (скорость обучения, по умолчанию 0.003, оптимально 0.001)
- $grad = \delta_l[j] \cdot a_{l-1}[k]$ — градиент веса (дельта × активация предыдущего слоя)
- $\delta$ — дельта нейрона

**Все градиенты ограничиваются** (gradient clipping) в диапазоне [-5.0, +5.0], чтобы предотвратить «взрыв градиентов» (gradient explosion).

**Интуиция**: Мы двигаем каждый вес в направлении, которое **уменьшает ошибку**. Размер шага определяется learning rate. Слишком большой lr → обучение нестабильно. Слишком маленький → обучение медленное.

### 7.8. Нормализация признаков (Z-score)

Перед подачей в сеть все признаки нормализуются по формуле Z-score:

$$x_{norm} = \frac{x - \mu}{\sigma}$$

Где:
- $\mu$ — среднее значение признака по датасету (featureMean)
- $\sigma$ — стандартное отклонение признака (featureStd)

**Зачем**: Признаки имеют **совершенно разные масштабы**. Например:
- `aimAngle` может быть 0-180 (градусы)
- `hitTimeDelta` может быть 0-5000 (миллисекунды)
- `speedXZ` может быть 0-1 (блоки/тик)

Без нормализации большие значения будут доминировать, а маленькие — игнорироваться. Z-score приводит все признаки к одному масштабу: среднее = 0, стандартное отклонение = 1.

**Важно**: Статистики `featureMean` и `featureStd` **вычисляются во время обучения** (по обучающему датасету) и **сохраняются в модели** (сериализуются вместе с весами). При предсказании (`predict()`) используются эти сохранённые статистики.

Если стандартное отклонение < 10⁻⁸ (признак почти константный), оно заменяется на 1.0, чтобы избежать деления на ноль.

### 7.9. Защита от числовых проблем

Сеть имеет несколько механизмов защиты от NaN и Infinity:

1. **Gradient Clipping (±5.0)**: Все градиенты при обратном распространении ограничены в [-5, +5]. Это предотвращает «взрыв градиентов», когда веса начинают получать огромные обновления.

2. **Sigmoid Clamping ([-500, 500])**: Вход sigmoid ограничен, чтобы `Math.exp(-x)` не переполнился.

3. **Z-score нормализация**: Приводит входы к удобному для сети диапазону, предотвращая ситуации когда веса или градиенты уходят в бесконечность.

4. **Epsilon в BCE (10⁻¹⁵)**: `Math.log(output + 1e-15)` предотвращает `log(0) = -∞`.

5. **Перезапуск весов при обучении**: При каждом вызове `train()` веса инициализируются заново (`initWeights()`), гарантируя чистый старт.

### 7.10. Инициализация весов (He Init)

Используется инициализация **He (2015)**, оптимальная для сетей с ReLU:

$$w_{init} \sim \mathcal{N}\left(0,\, \sqrt{\frac{2}{fan_{in}}}\right)$$

Где $fan_{in}$ — количество входных связей нейрона (размер предыдущего слоя).

```java
double scale = Math.sqrt(2.0 / layerSizes[l - 1]); // He init
weights[l][j][k] = rng.nextGaussian() * scale;
```

**Зачем**: Если веса слишком большие → взрыв градиентов. Слишком маленькие → затухание. He Init балансирует дисперсию активаций по слоям, обеспечивая стабильное обучение.

Все bias инициализируются нулями. Random seed = 42 (для воспроизводимости).

### 7.11. Потокобезопасность

Сеть использует `ReentrantReadWriteLock`:

- **`predict()`** берёт `readLock` — несколько потоков могут одновременно делать предсказания
- **`train()`** берёт `writeLock` — блокирует все предсказания на время обучения
- **`saveTo()`** и **`evaluate()`** берут `readLock`

Поле `lock` помечено как `transient` (не сериализуется). После десериализации создаётся новый lock через `ensureLock()`.

## 8. Сэмплы и датасет

### 8.1. Что такое сэмпл

**Сэмпл (sample)** — это один обучающий пример. Он состоит из:

1. **Вектор признаков** (`double[158]`) — числовое описание боевой ситуации (8 ударов + агрегаты)
2. **Метка (label)** — `0.0` (легитимный игрок) или `1.0` (читер)

Сэмпл создаётся в момент удара игрока, для которого активна сессия сбора данных. При каждом ударе `FeatureExtractor.extract()` вызывается с текущими данными `PlayerTracker` и создаёт вектор из 158 чисел.

### 8.2. Категории данных

Датасет разделён на **3 категории** — каждая хранится в отдельном CSV-файле:

| Файл | Категория | Метка | Описание |
|------|-----------|-------|----------|
| `legit.csv` | legit | 0.0 | Удары обычного игрока без читов |
| `cheatsnap.csv` | cheatsnap | 1.0 | Удары с Snap-аурой (мгновенное наведение) |
| `cheatsmooth.csv` | cheatsmooth | 1.0 | Удары с Smooth-аурой (плавное наведение) |

Обе чит-категории имеют одинаковую метку `1.0` — сеть учится отличать **любой тип аура** от человека.

Разделение на snap и smooth нужно для:
- Контроля баланса — чтобы знать, на каких данных обучена модель
- Разнообразия данных — модель видит оба типа читов

### 8.3. CSV-формат хранения

Файлы хранятся в `plugins/daynac/data/`:

```csv
f0,f1,f2,...,f157
0.234560,1.567890,0.001234,...,0.987654
0.345670,2.678901,0.002345,...,0.876543
...
```

- Первая строка — заголовок (`f0,f1,...,f157`)
- Каждая последующая строка — один сэмпл (158 чисел через запятую)
- Числа записаны с 6 знаками после точки (`%.6f`)
- Кодировка UTF-8

При чтении заголовочная строка автоматически пропускается.

### 8.4. Сбор данных

Процесс сбора данных в реальном времени:

1. Администратор вводит `/daynac data <категория> <ник>` — начинается сессия сбора
2. Целевой игрок помечается как «собирающий данные» в `CombatListener`
3. **Каждый удар** этого игрока записывается:
   - `PlayerTracker.recordHit()` → `HitData`
  - `FeatureExtractor.extract()` → `double[158]`
   - Вектор добавляется в `collectedSamples`
4. **Детекция пропускается** для игрока, у которого идёт сбор (иммунитет)
5. Администратор повторяет ту же команду — сбор останавливается
6. Все собранные сэмплы записываются в CSV через `DatasetManager.addSamples()`

## 9. Обучение модели

### Процесс обучения (при вызове `/daynac train`):

```
1. Проверить что датасет не пуст (≥ 10 сэмплов)
2. Запустить обучение в отдельном потоке (CompletableFuture.runAsync)
3. Загрузить все сэмплы и метки из DatasetManager
4. Перемешать данные (seed=42) и разделить 80% train / 20% validation
5. ИНИЦИАЛИЗАЦИЯ ВЕСОВ — weights и biases генерируются заново (He Init, seed=42)
6. ВЫЧИСЛИТЬ НОРМАЛИЗАЦИЮ — computeNormStats() по TRAIN-части (без утечки данных)
7. Нормализовать train и val одними и теми же статистиками
8. Для каждой эпохи:
   a. Обучение на 80% (forward + backward + SGD)
   b. Каждые N эпох — оценка val loss
   c. Если val loss улучшился — сохранить снимок весов (best weights)
   d. Если val loss не улучшался patience проверок подряд — EARLY STOP
9. Восстановить лучшие веса (best weights restore)
10. Вычислить точность на train и val отдельно
11. Сохранить модель в model.dat
12. Показать: train acc, val acc, лучшая эпоха, early stop, диагностика переобучения
```

### Validation Split (80/20)

Данные перемешиваются с фиксированным seed=42 и разделяются:

| Набор | Доля | Назначение |
|-------|------|------------|
| Train | 80% | Обучение весов (backprop + SGD) |
| Val | 20% | Оценка качества, early stopping, детекция переобучения |

**Важно**: Нормализационные статистики (mean/std) вычисляются только по train-части, чтобы избежать утечки данных (data leakage).

### Автоматический подбор эпох (Early Stopping)

Вместо ручного подбора числа эпох, система автоматически останавливает обучение, когда модель перестала улучшаться на валидационных данных:

```
ValCheckInterval = max(1, min(5, maxEpochs/50))

Каждые ValCheckInterval эпох:
  Вычислить val_loss (средний BCE на 20% данных)
  Если val_loss < best_val_loss:
    best_val_loss = val_loss
    best_epoch = текущая эпоха
    stale_count = 0
    Сохранить снимок всех весов (snapshot)
  Иначе:
    stale_count++
  Если stale_count ≥ patience:
    Остановить обучение (EARLY STOP)
    Восстановить лучшие веса из снимка
```

**Параметры**:
- `epochs: 0` — авто-режим (макс. 1000 эпох, patience авто-включается)
- `epochs: N` — фиксированный максимум N эпох
- `patience: 15` — остановка после 15 проверок без улучшения (0 = отключено)

**Восстановление лучших весов**: При early stop веса откатываются к состоянию лучшей эпохи (best epoch). Это гарантирует, что сохраняется не последняя (возможно переобученная), а оптимальная модель.

### Что такое «эпоха»

**Эпоха (epoch)** — это один полный проход через **весь** датасет. Если у вас 12 000 сэмплов и 120 эпох, то сеть увидит каждый сэмпл 120 раз.

С каждой эпохой:
- Loss (средняя ошибка) должна **уменьшаться**
- Веса **постепенно настраиваются** на распознавание читерских паттернов

### Прогресс обучения

Каждые ~5% эпох отправляется сообщение администратору:


Прогресс-бар из 20 символов, текущая эпоха, train loss, val loss и val accuracy.

При следующем запуске сервера модель загружается автоматически.

## 10. Система детекции: DetectionEngine

### 10.1. Асинхронный анализ ударов

Inference (предсказание) выполняется **асинхронно** в отдельном пуле потоков:

```java
ExecutorService inferencePool = Executors.newFixedThreadPool(2, ...);
// 2 daemon-потока с именем "Daynac-Inference"
```

Процесс анализа одного удара:

```
[Главный тик-поток]
  1. CombatListener.onDamage() вызывает engine.analyzeHitAsync()
  2. FeatureExtractor.extract() — быстро, на главном потоке
  3. CompletableFuture.supplyAsync(model::predict) — передаётся в пул

[Пул inference (async)]
  4. NeuralNetwork.predict(features) — прямой проход, нормализация + 4 слоя
  5. Результат (0.0-1.0) сохраняется в predictions[player]
  6. Scheduler.runTask() — передача обратно на главный поток

[Главный тик-поток]
  7. handlePrediction() — проверка порогов, оповещение, наказание
```

Это значит, что **тяжёлые вычисления нейросети не блокируют TPS сервера**.

### 10.2. Пороги детекции

| Порог | Значение | Действие |
|-------|----------|----------|
| `flag-threshold` | 0.65 | Оповестить администраторов о подозрительном игроке |
| `reduce-threshold` | 0.70 | Начать снижать урон от ударов |
| `cancel-threshold` | 0.90 | Полностью отменять урон |
| `punish-threshold` | 0.95 | Автоматическое наказание (если среднее последних ≥ порога) |

### 10.3. Градуированный урон

Система не просто «разрешает или отменяет» урон — она **плавно снижает** его:

```
Вероятность < 0.70  →  множитель = 1.0  (полный урон)
0.70 ≤ вероятность < 0.90  →  множитель = 1 / (1.2 + t × 0.3)
                                где t = (prob - 0.70) / (0.90 - 0.70)
                                т.е. делитель от 1.2 до 1.5
Вероятность ≥ 0.90  →  множитель = 0.0  (урон полностью отменён)
```

Пример: при вероятности 0.80 (середина промежутка), делитель = 1.35, множитель ≈ 0.74, урон = 74% от оригинала.

Это позволяет **не наказывать ложные срабатывания слишком жёстко** — если система «не уверена», урон просто немного снижается.

### 10.4. Автоматическое наказание

Наказание срабатывает при двух условиях:

1. Последнее предсказание ≥ `punish-threshold` (0.95)
2. **Среднее** всех сохранённых предсказаний (до 10 штук) ≥ `punish-threshold`

Второе условие — защита от **единичных ложных срабатываний**. Даже если одно предсказание = 0.99, но остальные 9 = 0.5, среднее = 0.55 < 0.95, и наказание не произойдёт.

Тип наказания задаётся в `config.yml`:
- `"kick"` — кик с сообщением
- `"ban"` — бан + кик
- `"none"` — ничего (только оповещение)

## 11. CombatListener: связь всех компонентов

`CombatListener` — центральный обработчик, соединяющий все системы:

### Тиковая задача (runTaskTimer, 1 tick):
```
Каждый тик → для каждого онлайн-игрока:
  PlayerTracker.recordSnapshot(player)
```

### Обработка удара (onDamage):
```
1. Проверить: дамагер — Player? entity — Player?
2. PlayerTracker.recordHit(attacker, victim) → HitData
3. Если attacker в режиме сбора данных:
  - FeatureExtractor.extract(recentHits) → features[158]
   - Добавить в collectedSamples
   - НЕ запускать детекцию (иммунитет)
4. Если модель готова И attacker НЕ в режиме сбора:
   - engine.analyzeHitAsync(attacker, victim) [async]
   - engine.getDamageMultiplier(attackerId) [sync, по предыдущим предсказаниям]
   - Если множитель = 0 → event.setCancelled(true)
   - Если множитель < 1 → event.setDamage(damage * multiplier)
```

**Важный нюанс**: Множитель урона рассчитывается по **предыдущим** предсказаниям (синхронно), а новое предсказание запускается асинхронно. Это значит, что первый удар всегда пропускается — нет данных, по которым судить.

## 12. Анимация наказания: PunishmentAnimation

Когда DetectionEngine решает наказать игрока, запускается анимированная последовательность:

### Фаза 1: Подъём (0-60 тиков = 3 секунды)

```
Каждый тик:
  1. Вычислить прогресс p = tick / 60  (от 0 до 1)
  2. Вычислить высоту: targetY = origin.Y + 3.0 * easeOutCubic(p)
     easeOutCubic(t) = 1 - (1 - t)³  ← быстрый старт, плавная остановка
  3. Телепортировать игрока на (origin.X, targetY, origin.Z)
  4. Обнулить скорость, включить полёт
  5. ЧАСТИЦЫ:
     - Две спирали (с разницей 180°) вокруг игрока:
       - Красная пыль (DustOptions) — оранжевая → красная по прогрессу
       - Soul Fire Flame — бирюзовое свечение
     - Столб Enchant-частиц от земли до игрока (каждые 3 тика)
  6. Звук ноты (bass) каждые 10 тиков — pitch нарастает с прогрессом
```

### Фаза 2: Кульминация (тик 65)

```
  1. Визуальная молния (strikeLightningEffect — без урона)
  2. Частицы: EXPLOSION, FLAME (40 штук), LAVA (20 штук)
  3. Звук взрыва
  4. Выброс инвентаря:
     - Все предметы из основного инвентаря
     - Все предметы брони
     - Предмет из левой руки
     - Каждый предмет получает случайный вектор скорости для разлёта
  5. Через 10 тиков (0.5 сек) → kick или ban
```

### Параметры анимации:

| Параметр | Значение | Описание |
|----------|----------|----------|
| `TARGET_HEIGHT` | 3.0 блока | Высота подъёма |
| `RISE_TICKS` | 60 (3 сек) | Длительность подъёма |
| `SPIRAL_RADIUS` | 1.2 блока | Радиус спирали частиц |
| `SPIRAL_SPEED` | 0.35 рад/тик | Скорость вращения спирали |

Спираль слегка сужается к вершине: `radius *= (1 - progress * 0.3)`.

```
Игрок A бьёт игрока B
         │
         ▼
[CombatListener.onDamage]
         │
         ▼
[PlayerTracker.recordHit(A, B)]
  • Берёт 3-4 последних снапшота A
  • Считает aimAngle(A→B), distance, hitTimeDelta
  • Собирает yawDeltas, pitchDeltas, hitTimes из истории
  • Вызывает FeatureExtractor.buildHitData() → HitData (19 чисел)
  • Сохраняет HitData в hitHistory[A]
         │
         ▼
[Проверка: A собирает данные?]
  ├── ДА → FeatureExtractor.extract() → features[158]
  │        Сохранить сэмпл для датасета. СТОП.
  │
  └── НЕТ + модель готова → продолжить
         │
         ▼
[DetectionEngine.analyzeHitAsync(A, B)]  ←─── ASYNC
  │
  ├──[Главный поток]──────────────────────────────────────┐
  │  getDamageMultiplier(A)                                │
  │  (по предыдущим предсказаниям)                        │
  │    <0.70 → полный урон                                │
  │    0.70-0.90 → урон × (1/1.2 .. 1/1.5)               │
  │    ≥0.90 → event.setCancelled(true)                   │
  │                                                        │
  └──[Пул inference (2 потока)]────────────────────────────┘
      1. FeatureExtractor.extract(recentHits) → features[158]
     2. NeuralNetwork.predict(features):
        a. normalize(features) — Z-score
        b. 158 → hidden1(128, ReLU)
        c. → hidden2(64, ReLU)
        d. → hidden3(32, ReLU)
        e. → output(1, Sigmoid) = probability
     3. Сохранить probability в predictions[A] (до 10 штук)
     4. → [Вернуться на главный поток]
        │
        ▼
   [handlePrediction]
     ├── prob ≥ 0.65: оповестить администраторов, добавить в flaggedPlayers
     ├── prob ≥ 0.95 И среднее ≥ 0.95:
     │     └── PunishmentAnimation.execute(A, "kick", reason)
     │           ├── Левитация 3 секунды + спираль частиц

     │           └── Kick/Ban через 0.5с
     └── иначе: ничего (данные сохранены для следующего раза)
```

## 17. Математические формулы

### Прямой проход нейрона j в слое l:

$$z_j^{(l)} = b_j^{(l)} + \sum_{k=0}^{n_{l-1}-1} w_{jk}^{(l)} \cdot a_k^{(l-1)}$$

$$a_j^{(l)} = \begin{cases} ReLU(z_j^{(l)}) & \text{если } l \neq L \\ Sigmoid(z_j^{(l)}) & \text{если } l = L \end{cases}$$

### Binary Cross-Entropy:

$$\mathcal{L} = -\left[y \ln(\hat{y} + \epsilon) + (1-y) \ln(1-\hat{y} + \epsilon)\right]$$

### Backpropagation — дельта выходного слоя:

$$\delta^{(L)} = \hat{y} - y$$

### Backpropagation — дельта скрытого слоя:

$$\delta_j^{(l)} = \text{clip}\!\left(\left[\sum_{n} w_{nj}^{(l+1)} \cdot \delta_n^{(l+1)}\right] \cdot ReLU'(a_j^{(l)}),\; -5,\; +5\right)$$

### Обновление весов (SGD):

$$w_{jk}^{(l)} \leftarrow w_{jk}^{(l)} - \eta \cdot \text{clip}(\delta_j^{(l)} \cdot a_k^{(l-1)},\; -5,\; +5)$$
$$b_j^{(l)} \leftarrow b_j^{(l)} - \eta \cdot \text{clip}(\delta_j^{(l)},\; -5,\; +5)$$

### Z-score нормализация:

$$x_i^{norm} = \frac{x_i - \mu_i}{\sigma_i}, \quad \sigma_i = \max\left(\sqrt{\frac{1}{N}\sum_{n=1}^{N}(x_i^{(n)} - \mu_i)^2},\; 10^{-8}\right)$$

### He инициализация:

$$w \sim \mathcal{N}\left(0,\; \sqrt{\frac{2}{fan_{in}}}\right)$$

### Коэффициент вариации:

$$CV = \frac{\sigma}{\mu} = \frac{\sqrt{\frac{1}{N}\sum(x_i - \bar{x})^2}}{\bar{x}}$$

### Энтропия Шеннона:

$$H = -\sum_{i=1}^{8} p_i \ln(p_i), \quad p_i = \frac{\text{count}_i}{N}$$

с 8 бинами: [0, 0.5), [0.5, 1), [1, 2), [2, 5), [5, 10), [10, 30), [30, 90), [90, ∞)

### Коэффициент детерминации (R²):

$$R^2 = r^2, \quad r = \frac{n\sum x_iy_i - \sum x_i \sum y_i}{\sqrt{(n\sum x_i^2 - (\sum x_i)^2)(n\sum y_i^2 - (\sum y_i)^2)}}$$

### Автокорреляция (lag-1):

$$\rho_1 = \frac{\sum_{i=0}^{n-2}(x_i - \bar{x})(x_{i+1}-\bar{x})}{\sum_{i=0}^{n-1}(x_i - \bar{x})^2}$$

### Градуированный множитель урона:

$$mult = \begin{cases} 1.0 & \text{если } p < 0.70 \\ \frac{1}{1.2 + 0.3 \cdot t} & \text{если } 0.70 \leq p < 0.90, \quad t = \frac{p - 0.70}{0.20} \\ 0.0 & \text{если } p \geq 0.90 \end{cases}$$

### easeOutCubic (для анимации):

$$f(t) = 1 - (1-t)^3$$

## Резюме

Daynac — это полноценная ML-система, работающая внутри Minecraft-сервера. Она:

1. **Собирает данные** — каждый тик записывает 9 параметров каждого игрока; при ударе вычисляет 19 признаков боевого события, включая `jerkValue`
2. **Формирует признаки** — агрегирует 8 последних ударов + 6 статистик = 158-мерный вектор
3. **Обучается** — на помеченных данных (legit/cheat) с помощью нейросети 158→128→64→32→1 через backpropagation + SGD
4. **Детектирует** — асинхронно классифицирует каждый удар, не нагружая сервер
5. **Реагирует** — градуированно: от предупреждения → снижения урона → полной отмены → анимированного бана/кика

Вся система реализована на чистом Java без внешних ML-библиотек, с полной потокобезопасностью, нормализацией данных и защитой от числовых проблем.
